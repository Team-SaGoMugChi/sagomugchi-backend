# 위기 발화 판정 기준

`app/services/counsel_guardrail.py`의 `assess()`가 사용자 발화 한 문장을 **위험 축**과 **단계**로 판정한다.
상담(`/counsel/turn`)과 일기 대화(`/diary/interview/turn`)가 같은 판정을 쓴다.

## 단계

| 단계 | 처리 | 사용자에게 보이는 것 |
|---|---|---|
| CRISIS | LLM을 부르지 않고 축에 맞는 안내. 응답 `crisis: true`, `risk_axis` → 앱이 상담 중단 | 축별 안내 배너·연락처 |
| CAUTION | 상담 계속. 시스템 프롬프트에 축별 안전 지침(`CAUTION_GUIDES`) 추가 | 평소 상담 (상담봇이 필요하면 부드럽게 확인) |
| NONE | 평소처럼 상담 | 평소 상담 |

## 위험 축

| 축 (`risk_axis`) | CRISIS | CAUTION | 연락처 |
|---|---|---|---|
| `suicide` 자살·자해 | 죽음 바람, 방법·계획, 간접 표현 | 부정·과거·남의 말·사소한 이유, 정보 맥락 | 자살예방상담전화 109 |
| `danger` 폭력 피해 | 지금 맞는 중, 누가 따라오는 중 | 과거 피해, 가정폭력·스토킹 언급 | 112, 여성긴급전화 1366 |
| `harm_others` 타해 | 흉기 + 대상 행동("칼 들고 찾아갈 거야") | "죽이고 싶다" 같은 분노 표현 | 1577-0199, 112 |
| `psychosis` 현실 검증 | 명령 환청("목소리가 ~하라고 해") | 감시·도청·환청 경험 | 정신건강위기상담전화 1577-0199 |
| `dependence` AI 의존 | 없음 | "너밖에 없어", "너랑 사귀고 싶어" | 사람 관계로 부드럽게 연결 |

여러 축이 걸리면 단계가 높은 쪽, 같으면 표의 위쪽 축을 고른다.
예: "목소리가 창문으로 뛰어내리라고 해" → 자살 축 CRISIS (109 안내가 우선).

## 자살 축 판정 순서

1. **방법·계획 표현** (자살, 자해, 유서를 쓰, 약을 모아, 뛰어내리, 인생 끝내…) → CRISIS
   - 단, 정보·제3자 맥락(뉴스, 영화, 예방, 친구가…)이고 본인 의도(하고 싶, 할까…)가 없으면 → CAUTION
2. **죽음·소멸 바람** (죽고 싶, 사라지고 싶, 살기 싫, 그만 살고 싶…) → CRISIS
   - 바로 뒤가 부정("죽고 싶진 않아", "죽고 싶다까지는 아닌데") → CAUTION
   - 바로 뒤가 과거("죽고 싶었던 적") → CAUTION
   - 제3자가 있고 전달 표현("친구가 죽고 싶다고 해") → CAUTION
   - "죽고 싶" 바로 앞이 신체·사소한 이유(배고파, 졸려, 웃겨…) → CAUTION
   - 위 경우라도 진심 표시(진짜로, 진심, 농담 아니고, 오늘 밤)가 있으면 → CRISIS
3. **간접 표현** (아침에 눈 안 떴으면, 살아있는 게 의미가 없어, 내가 죽으면, 한강 가고 싶…) → CRISIS
   - "끝내버리고 싶다"는 과제·프로젝트 같은 대상이 없을 때만 해당
4. **모호한 표현** (죽을래, 죽어야지) → CAUTION (진심 표시가 있으면 CRISIS)
5. 나머지 → NONE. "죽겠다 / 죽을 것 같다 / 죽는 줄"은 한국어 강조 표현이라 여기에 해당한다.

## 정한 이유

- **"죽겠다"는 안 잡고 "죽고 싶다"는 잡는다.** "~해 죽겠다"는 강조로 굳은 표현이고, "죽고 싶다"는 바람을 직접 말한다.
- **마음의 고통이 이유인 "죽고 싶다"는 낮추지 않는다.** 힘들어·우울해·외로워·지쳐는 실제 위기의 흔한 표현이다.
- **간접 표현을 잡는다.** PR3 평가에서 놓친 문장이 모두 "죽음"이라는 말 없이 삶을 멈추고 싶다는 뜻을 담은 말이었다.
- **웃음(ㅋㅋ)은 근거로 쓰지 않는다.** 위기를 웃음으로 감추는 경우가 있다.
- **애매하면 CAUTION.** 사용자 화면에는 변화가 없어 오탐 비용이 낮고, 상담봇이 대화 맥락으로 한 번 더 거른다.
- **AI 의존은 CRISIS로 만들지 않는다.** 상담을 끊으면 오히려 고립감을 키운다. 상담봇이 사람 관계로 연결한다.
- **방법·도구는 상담봇이 어떤 경우에도 구체적으로 말하지 않는다.**

## 성능 확인

`python -X utf8 scripts/evaluate_counsel.py`로 잰다. 결과는 `docs/evaluations/`에 저장된다.

- **개발 세트**: 규칙을 만들며 본 문장. 항상 100%를 유지해야 한다(`tests/test_evaluate_counsel.py`).
- **검증 세트**: 규칙을 다 쓴 뒤에 적은 문장. 실제 성능은 이 숫자로 말한다.
  결과를 보고 규칙을 고쳤다면 그 문장은 개발 세트로 옮기고, 검증 세트에는 새 문장을 채운다.

## 한계

키워드 기반 1차 거름망이라 모든 문맥을 이해하지 못한다(검증 세트 기준 정확도는 평가 결과 참고).
오탐·미탐 사례를 발견하면 먼저 검증 세트에 넣어 기록한 뒤 규칙을 고친다.
